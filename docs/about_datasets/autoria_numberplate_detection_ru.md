# AUTO.RIA Numberplate Dataset (Detection) — `autoriaNumberplateDataset-2021-05-12`

## Общая информация

**AUTO.RIA Numberplate Dataset** — детекционный корпус полных кадров автомобилей с полигональной разметкой номерных пластин, опубликованный проектом **Nomeroff Net** (GitHub `ria-com/nomeroff-net`). Данные предоставлены сервисом объявлений **AUTO.RIA.com** (правообладатель **ARS Online OU**, copyright 2018–2020) и выложены в открытый доступ. Версия `2021-05-12` — снимок детекционного датасета, на котором в валидационной кампании CARS закрепляется проверка стадии **LP Detection** (модель `nomeroff_lpd` = `yolov11x-keypoints-2026-01-21.pt`, детектор 4 угловых точек пластины).

Ключевые числа локальной копии: **8042 размеченных изображения** (train 7666 + val 376), **8651 регион** разметки пластин (8648 полигонов + 3 региона `rect`), формат аннотаций — **VGG Image Annotator (VIA)** с полигональными (четырёхугольными) контурами. Каждый полигон описывает наклонённую/перспективную пластину 4 угловыми точками — что напрямую соответствует выходу keypoint-детектора `nomeroff_lpd`.

## Формат изображений

- **Тип контента:** полный кадр автомобиля (реальное фото объявления AUTO.RIA), не кроп пластины.
- **Форматы файлов:** преимущественно JPEG (`.jpeg`/`.jpg`), небольшая доля PNG.
- **Разрешение:** переменное (исходные фото объявлений разного размера и качества).
- **Цветовое пространство:** RGB.
- **Качество/ракурс:** переменные — реальные пользовательские снимки, различные расстояния, углы, освещение.
- **EXIF:** возможна нетривиальная ориентация (для нормализации в составе датасета поставляется `bin/fixexif.sh`, обрабатывающий `.jpeg`).

## Формат аннотаций

Аннотации хранятся в `via_region_data.json` — это **полный проектный экспорт VGG Image Annotator (VIA)**, а не упрощённый словарь регионов. На верхнем уровне три ключа:

- `_via_settings` — настройки проекта VIA (содержат абсолютные пути исходного автора — артефакт);
- `_via_img_metadata` — словарь разметки изображений (ключ = `имя_файла` + `размер_в_байтах`);
- `_via_attributes` — описание схемы атрибутов региона/файла (в этом датасете пустое: `{"region": {}, "file": {}}` — атрибуты заданы ad-hoc на уровне регионов).

Каждая запись в `_via_img_metadata` описывает одно изображение: `filename`, `size`, массив `regions`, `file_attributes`. Регион пластины задаётся полигоном:

```json
{
  "369359862-1.jpeg": {
    "filename": "369359862-1.jpeg",
    "size": 227668,
    "regions": [
      {
        "shape_attributes": {
          "name": "polygon",
          "all_points_x": [177, 370, 364, 171],
          "all_points_y": [408, 402, 463, 465]
        },
        "region_attributes": {}
      }
    ],
    "file_attributes": {}
  }
}
```

### Поля региона

| Поле | Тип | Семантика |
|------|-----|-----------|
| `shape_attributes.name` | str | Тип фигуры: `"polygon"` (норма) либо редкие `"rect"` (3 шт. в train) |
| `shape_attributes.all_points_x` | int[] | X-координаты вершин полигона (абс. пиксели), обычно 4 точки |
| `shape_attributes.all_points_y` | int[] | Y-координаты вершин полигона (абс. пиксели), обычно 4 точки |
| `region_attributes.class` | str | Класс региона; где задан — `"numberplate"` (иначе пусто) |

> Поле `region_attributes.class` заполнено непоследовательно: в train `"numberplate"` проставлен у 1587 регионов, у 6659 атрибут пуст; в val `"numberplate"` у 389, пусто у 16. Для задачи детекции это несущественно — единственный размечаемый класс в датасете — пластина.

## Использование для CarCV

### Применимость

- ✅ **Валидация LP Detection** (`nomeroff_lpd` = `yolov11x-keypoints-2026-01-21.pt`) — основная цель. 8042 кадра с GT-разметкой пластин достаточны для статистически значимой оценки Precision/Recall детектора.
- ✅ **Полигональная (четырёхугольная) разметка идеально ложится на keypoint-выход** `nomeroff_lpd`: 4 угловые точки пластины из GT сопоставимы с 4 предсказанными keypoints напрямую (метрика по углам / OKS).
- ✅ **Сведение к bbox-метрикам**: полигон тривиально сводится к axis-aligned bbox через `min/max` по `all_points_x`/`all_points_y` для расчёта IoU, Precision, Recall.
- ✅ **Полные кадры** (а не кропы) — даёт реалистичный тест локализации пластины в сцене, включая кадры с несколькими пластинами.
- ✅ **Лицензия CC BY 4.0** — безопасна для коммерческой валидации и публикации метрик при указании авторства.

### Ограничения

- ⚠️ **Украинский авторынок (AUTO.RIA)** → среди сцен преобладают UA/смешанные номера. Для стадии LP Detection это **несущественно**: детектор локализует пластину как объект и не распознаёт текст, поэтому страновая принадлежность номера на этом этапе значения не имеет (текст разбирается отдельной моделью OCR `nomeroff_ocr`).
- ⚠️ **VIA-формат, не YOLO/COCO** — требуется конвертация полигонов в keypoints/bbox перед прогоном (см. Рекомендации).
- ⚠️ **Непоследовательный `region_attributes.class`** — нельзя полагаться на наличие `"numberplate"`; класс единственный, фильтровать по нему не нужно.
- ⚠️ **Переменное качество/ракурс** реальных объявлений — занижает абсолютные метрики, но это и есть целевое распределение «реальных условий».
- ❌ **Не покрывает другие стадии CARS**: нет аннотаций марки/типа/цвета (TrafficCamNet, VehicleMakeNet, VehicleTypeNet), нет лиц (FaceDetect), нет текста номера для OCR (`nomeroff_ocr`).
- ⚠️ **Сценарии §5.1 покрыты частично**: фото статичные (нет управляемых day/night/IR и диапазона 0–60 км/ч); ракурс/дистанция близки к §5.1 (0–30°, 5–50 м), но не контролируются.

### Рекомендации

1. **Целевой прогон — `nomeroff_lpd`.** Использовать `val/` (376 изображений, 405 полигонов) как primary benchmark LP Detection; `train/` (7666) — как расширенный/holdout-набор, но **не как обучающий** при валидации (риск перекрытия с обучающим корпусом nomeroff-net-моделей).
2. **Подтверждение PASS.** Прошлый прогон на детекционном датасете AUTO.RIA версии 2019 дал PASS (Precision=0.91, Recall=0.92); на версии `2021-05-12` повторить расчёт Precision/Recall и зафиксировать вердикт по тем же порогам. FAIL — валидный результат, не повод для тюнинга.
3. **Keypoint-метрика (приоритет).** Сопоставлять 4 GT-угла полигона с 4 предсказанными keypoints `yolov11x-keypoints` напрямую (например, через OKS или среднюю ошибку угла), отбрасывая редкие полигоны с ≠4 точками или приводя их к 4 углам.
4. **Bbox-метрика (вспомогательно).** Сводить каждый полигон к axis-aligned bbox:
   ```python
   import json
   from pathlib import Path

   def via_polygons_to_bboxes(via_json_path):
       d = json.load(open(via_json_path, encoding="utf-8"))
       md = d.get("_via_img_metadata", d)  # поддержка полного экспорта VIA
       out = {}
       for entry in md.values():
           boxes = []
           for r in entry.get("regions", []):
               sa = r["shape_attributes"]
               if sa.get("name") != "polygon":
                   continue  # редкие rect — обработать отдельно
               xs, ys = sa["all_points_x"], sa["all_points_y"]
               boxes.append((min(xs), min(ys), max(xs), max(ys)))
           out[entry["filename"]] = boxes
       return out
   ```
5. **Учитывать мульти-пластинные кадры** (до 8 пластин на изображение в train) при подсчёте Recall — каждый GT-полигон считается отдельным объектом.
6. **Нормализовать EXIF-ориентацию** перед инференсом (поставляемый `bin/fixexif.sh`), чтобы координаты разметки совпадали с пиксельной геометрией декодированного изображения.
