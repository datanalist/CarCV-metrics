# VMMRdb Dataset

## Общая информация

**VMMRdb** (Vehicle Make and Model Recognition Dataset) — крупномасштабный fine-grained датасет для распознавания марки, модели и года выпуска транспортных средств. Опубликован Faezeh Tafazzoli, Hichem Frigui и Keishin Nishiyama (University of Louisville) в работе «A Large and Diverse Dataset for Improved Vehicle Make and Model Recognition» на воркшопе CVPR 2017 (IEEE CVPR Workshops, DOI 10.1109/CVPRW.2017.121). Каждое изображение размечено меткой *make + model + production year*.

Официальный объём датасета — **9 170 классов** и **291 752 изображения**, покрывающих модели **1950–2016** годов. Изображения краудсорсены пользователями (рынок США); по README данные покрывают **712 areas по всем 412 sub-domains, соответствующим US metro areas**. Снимки сделаны разными пользователями, разными устройствами и под разными ракурсами; автомобили часто не выровнены, присутствует посторонний фон, окклюзии и низкая освещённость. README не называет конкретный источник фото (классифайды/Craigslist-подобные источники указываются во вторичных описаниях, но в официальном README источник не уточнён).

**Официальный репозиторий:** https://github.com/faezetta/VMMRdb
**Paper (CVPR 2017 Workshops, open access):** https://openaccess.thecvf.com/content_cvpr_2017_workshops/w9/html/Tafazzoli_A_Large_and_CVPR_2017_paper.html

> **Примечание о локальной копии.** Локально доступно **285 086 изображений** (281 752 `.jpg` + 3 334 `.png`) при полном составе **9 170 каталогов-классов** (~13 GB на диске). Это меньше официальных 291 752 изображений (фактический объём загруженной копии). Кроме того, в корне присутствует **пустой 0-байтовый файл-маркер `for_VMN_model`** — это **локальный артефакт проекта CARS**, а **не** часть оригинального VMMRdb и **не** каталог с изображениями.

## Структура датасета

Датасет организован по принципу «один каталог = один класс». Имя каталога является меткой класса в формате `make_model_year` (марка и модель могут содержать пробел, см. ниже). Каждый каталог-класс заканчивается 4-значным токеном года (исключений на диске нет).

```
/home/mk/Загрузки/DATASETS/VMMRdb/
├── acura_cl_1997/                       # класс = имя каталога (40 изображений)
│   ├── acura_cl_1997_0.jpg
│   ├── acura_cl_1997_1.jpg
│   └── ...
├── acura_cl_2002/                       # 8 изображений (long-tail)
├── acura_integra_1900/                  # 1900 — плейсхолдер «год неизвестен»
├── ...
├── mercedes benz_e320_1994/             # пробел в make ("mercedes benz")
├── ford_crown victoria_1985/            # пробел в model ("crown victoria")
├── landrover_.../                       # слитная марка ("landrover")
├── rollsroyce_.../                      # слитная марка ("rollsroyce")
├── ...                                  # всего 9 170 каталогов-классов
└── for_VMN_model                        # ЛОКАЛЬНЫЙ артефакт CARS: пустой файл-маркер (не часть VMMRdb)
```

## Формат изображений

- JPEG (`.jpg`, ~98.8 % файлов) и PNG (`.png`, ~1.2 %), переменное разрешение.
- Цветовое пространство: RGB.
- Содержание: автомобили из объявлений о продаже — frontal / rear / 3-quarter / интерьер, разные устройства съёмки, неравномерное выравнивание, посторонний фон, окклюзии, ночные/низкоосвещённые кадры.
- Имена файлов внутри класса: в основном `{make}_{model}_{year}_{N}.jpg`; встречаются также оригинальные имена из источника (например, `2002 Acura 3.2 Cl coupe_01717_50NZwcJDVg0_600x450.jpg`).

## Формат аннотаций

В VMMRdb **нет отдельных файлов аннотаций** (нет JSON/CSV/`.mat`). Единственная разметка — **имя каталога**, в котором лежит изображение. Метка класса = имя каталога вида `make_model_year`.

```python
import os, re

def parse_vmmrdb_label(dirname: str):
    """
    Разбор метки каталога VMMRdb в (make, model, year).
    Особенности именования:
      - год = последний токен по '_'; '1900' = плейсхолдер 'год неизвестен';
      - make может содержать пробел: 'mercedes benz', 'alfa romeo',
        'aston martin', 'am general', 'can am';
      - слитные марки: 'landrover', 'rollsroyce';
      - model может содержать пробел/несколько токенов:
        'ford_crown victoria_1985', 'mercedes benz_e320_1994'.
    Поэтому: год берётся как последний токен, make — по справочнику,
    model — всё между make и годом.
    """
    tokens = dirname.split('_')
    year = tokens[-1]                 # '1900'..'2017'; '1900' = unknown
    make = tokens[0]                  # ВНИМАНИЕ: см. caveats ниже
    model = '_'.join(tokens[1:-1])
    return make, model, year
```

| Поле | Источник | Описание |
|------|----------|----------|
| `make` | первый токен имени каталога (по `_`) | марка; **многословные марки содержат пробел** (`mercedes benz`, `alfa romeo`, `aston martin`, `am general`, `can am`); слитные — `landrover`, `rollsroyce` |
| `model` | токены между маркой и годом | модель; может содержать пробел/несколько токенов (`crown victoria`, `e320`) |
| `year` | последний токен (всегда `^[0-9]{4}$`) | год выпуска; диапазон `1900`–`2017`; **`1900` — плейсхолдер «год неизвестен»** (напр. `acura_integra_1900`; всего 14 каталогов с `_1900`) |
| метка изображения | имя родительского каталога | полный класс `make_model_year` |

> **Важно для парсинга make.** Сплит по `_` корректно даёт первый токен с учётом пробела внутри (`mercedes benz` останется одним first-token при `split('_')`), но для модели и для отбора 20 марок CARS требуется аккуратный mapping: построить справочник `vmmrdb_make_token -> CARS_make` (в частности `mercedes benz -> Mercedes`) и не полагаться на простое равенство строк.

## Использование для CarCV

В кампании валидации VMMRdb используется для проверки **VehicleMakeNet** (NVIDIA TAO, pruned) — задача «Make». Заменяет суррогатный датасет mad-cars. Цели §6.3: 20 марок, **Top-1 > 0.70**, **Top-3 > 0.85**.

### Применимость

- ✅ **Vehicle Make (Top-1 > 0.70, Top-3 > 0.85)** — primary benchmark. Все 20 марок CARS §6.3 присутствуют (плюс ~55 других токенов марки), что позволяет сформировать сбалансированный по марке срез.
- ✅ Большой объём и разнообразие (285 086 локальных изображений, разные устройства, ракурсы, освещение) — устойчивая оценка вне «каталожного» домена.
- ✅ Метка make/model/year выводится из имени каталога — не нужен парсинг внешних файлов аннотаций.
- ✅ Подходит для построения confusion matrix по 20 маркам (Honda↔Acura, Lexus↔Toyota и т.п.) и анализа ошибок по году выпуска.

### Ограничения

- ❌ **Лицензия покрывает только репозиторий (MIT), но не права на фотографии.** Изображения краудсорсены пользователями (рынок США), авторские права на фото принадлежат разным владельцам → для коммерческого продукта CARS обязателен legal review (см. «Лицензия»).
- ⚠️ **Доменный сдвиг.** Снимки — каталожные/объявленческие ракурсы (часто статичная съёмка с близкого расстояния, интерьеры), а не automotive POV §5.1 (дистанция 5–50 м, угол 0–30°, скорость 0–60 км/ч, day/night/IR). Метрики на VMMRdb могут переоценивать качество относительно бортового сценария.
- ⚠️ **Сильный дисбаланс классов (long-tail)** — от 8 изображений на класс до тысяч; макро-усреднение по марке обязательно, иначе доминируют Chevrolet/Ford/BMW.
- ⚠️ **Возможный train/test leak.** VehicleMakeNet обучен на US-данных; VMMRdb — тоже US-рынок. Нельзя исключать пересечение обучающей выборки VehicleMakeNet с VMMRdb → результат может быть оптимистично смещён.
- ⚠️ **Нет bbox-аннотаций.** Кадр содержит посторонний фон; для входа VehicleMakeNet (crop) нужен предварительный детектор/кроп.
- ⚠️ **Грязные метки года:** `1900` — плейсхолдер «неизвестно» (14 каталогов); присутствуют годы до 2017 при официальном диапазоне 1950–2016.
- ❌ Нет аннотаций номерных знаков, типов кузова (явных), цвета, лиц — задачи LPD/OCR/Type/Color/Face этот датасет не покрывает.

### Рекомендации (валидация VehicleMakeNet, §6.3: Top-1 > 0.70 / Top-3 > 0.85)

1. **Mapping make → 20 марок CARS.** Построить справочник `docs/about_datasets/vmmrdb_make_to_cars.csv` (`vmmrdb_make_token` → один из 20 CARS makes), в частности `mercedes benz → Mercedes`. Отобрать **только** пересекающиеся классы (19 токенов + `mercedes benz`); остальные ~55 токенов марки исключить из подсчёта.
2. **Метки VehicleMakeNet ↔ VMMRdb.** VehicleMakeNet выдаёт 20 классов марок; сопоставить их с CARS-метками 1:1 и игнорировать классы вне пересечения при расчёте Top-1/Top-3.
3. **Макро-усреднение.** Из-за long-tail считать Top-1/Top-3 **по марке (macro-average)**, а не micro: `Top1_macro = mean_over_20_makes(accuracy_make)`. По желанию — сбалансировать срез (cap N изображений на марку).
4. **Кроп под вход модели.** VehicleMakeNet ожидает crop ТС (224×224). Использовать детектор (TrafficCamNet) для извлечения кропа из кадра вместо подачи полного изображения с фоном.
5. **Вердикт pass/fail.** Top-1 > 0.70 и Top-3 > 0.85 на сбалансированном по марке срезе. **FAIL — валидный результат** (вероятен из-за доменного сдвига объявления→automotive POV), фиксируется как есть, без тюнинга.
6. **Контроль leak.** При интерпретации высоких метрик отметить риск пересечения обучающих US-данных VehicleMakeNet с VMMRdb; по возможности сверить с независимым доменным срезом (например, BDD/UA-DETRAC-подобным).
7. **Чистка меток.** Исключить/пометить классы с `year=1900` при анализе по году; не использовать год как фактор качества.
