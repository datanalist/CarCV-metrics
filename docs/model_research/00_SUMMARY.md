# Исследование открытых моделей-аналогов для стека CARS — сводка

> **См. также:** реестр моделей — [models.md](../../models.md) · исследование датасетов-аналогов — [../dataset_research/00_SUMMARY.md](../dataset_research/00_SUMMARY.md) · детальные файлы по задачам — раздел «Детальные файлы».

## Цель и метод

Для каждой модели из `models.md` подобраны открытые предобученные **аналоги**, пригодные для пайплайна CARS на NVIDIA Jetson Orin Nano 8GB (DeepStream + TensorRT FP16/INT8 либо Python-сервис на ONNX Runtime). Метод: веб-поиск по первоисточникам (GitHub, Hugging Face, NVIDIA NGC, OpenVINO Open Model Zoo, OpenCV Zoo, PaddlePaddle), **адверсариальная** проверка лицензий под коммерческий продукт, оценка edge-пригодности (бюджет Orin Nano, наличие пути ONNX→TensorRT) и домен-fit к **бортовому POV** (уровень дороги, дистанция ~5–50 м, режимы day/night/IR; RU/UA/СНГ для номеров и OCR). Охвачено 8 задач.

**Адверсариальный принцип по лицензиям:** любая неопределённость (`unclear`, отсутствие SPDX, «research/academic only», email-agreement) трактуется как «по умолчанию запрещено до legal review». Блокеры коммерции: `NC` (non-commercial), `ND`, `AGPL-3.0` и `GPL-3.0` (сильный copyleft). Чистые: `Apache-2.0`, `MIT`, `BSD`, `CC BY 4.0` (различаем CC BY на **веса** vs на **код**). Явно проверены известные ловушки: (1) **Ultralytics YOLO** (v5/v8/v11/v12) — `AGPL-3.0` → copyleft-блокер, нужна платная Enterprise-лицензия; (2) предобученные веса **InsightFace** (buffalo_l/antelopev2, SCRFD, RetinaFace, ArcFace) — **non-commercial research only**, хотя КОД MIT; (3) **NVIDIA TAO/NGC** — `NVIDIA Model EULA`, коммерческий деплой/редистрибуция весов и engine требуют подтверждения; (4) **OpenVINO OMZ** — обычно `Apache-2.0` (чисто). README «MIT» не доверяем, если веса под отдельной лицензией.

**Важная оговорка:** все цифры точности — «по заявлению авторов, не измерено нами»; латентность на Orin Nano (особенно DETR-семейства) требует отдельного замера.

## Краткие итоги по задачам

### 1. Detection — детекция транспортных средств и участников движения: TrafficCamNet
**Detection (PGIE) — аналоги TrafficCamNet.** Готового drop-in коммерчески-чистого аналога нет: лучший domain-fit (**DashCamNet**, тот же DetectNet_v2 + dashcam POV) под NVIDIA Model EULA (unclear/блокер, чист только производный fine-tune). Чистые Apache-2.0-веса (**D-FINE**, **RF-DETR Core**, PP-YOLOE+, YOLOX, RT-DETRv2, NanoDet) обучены на COCO/Objects365 (web POV) → domain gap к бортовому POV, нет RU/UA. **Ultralytics YOLO (AGPL)** и **YOLO-NAS (NC-веса)** — лицензионные блокеры. Точность не измерена нами; латентность DETR на Orin Nano требует замера. Вердикт: брать Apache-2.0 модель под edge + fine-tune на собственном бортовом RU/UA-датасете (DashCamNet — domain-релевантная инициализация после legal review).
**Детально:** `docs/model_research/01_detection_trafficcamnet.md`

### 2. LP Detection — детекция номерного знака (+ опц. 4 угла): nomeroff_lpd
**LP Detection (nomeroff_lpd, YOLO11x-pose, bbox+4 угла):** валидный отрицательный результат — открытого предобученного аналога, который одновременно (а) лицензионно чист для коммерции, (б) выдаёт 4 угла пластины и (в) обучен на RU/UA ГОСТ-Р, **не существует**. 4 угла дают только `we0091234`/`xialuxi`/`WPOD-NET` — все заблокированы GPL/AGPL/unclear + домен CCPD. Чистая Apache-2.0 — только у `PaddleOCR det`, но это детектор текста, не пластины. Лёгкий `open-image-models` (YOLOv9, MIT-код) снимает риск тяжести YOLO11x, но веса unclear (YOLOv9 из GPL-3.0) и только bbox. `NVIDIA LPDNet` уже отвергнут в CARS с доказанным FAIL R≈0.30 на RU/UA. Рекомендация: дообучение собственной keypoint-головы на AUTO.RIA с чистой базы (не Ultralytics-AGPL/не WongKinYiu-GPL); либо bbox open-image-models + PaddleOCR-warp при отказе от keypoints (оба — после legal review).
**Детально:** `docs/model_research/02_lpd_nomeroff.md`

### 3. Face Detection — детекция лиц: FaceDetect (NVIDIA FaceNet)
**Face Detection (FaceDetect / NVIDIA FaceNet, DetectNet_v2 ResNet-18).** Топ-аналоги: **YuNet** (OpenCV Zoo, подтверждённая MIT на код+веса, ~0.083M params, готовый ONNX + ONNX→TensorRT на Jetson) — primary для дня/RGB; **NVIDIA FaceDetectIR** — единственный аналог со штатным покрытием IR/ночи (та же DetectNet_v2 → переиспользование декодера ~1:1), primary для ночи/ИК, но Model EULA требует legal review перед внешней поставкой. Secondary — ULFG-1MB (MIT, минимальный вес) и MediaPipe BlazeFace (Apache-2.0, но «селфи»-профиль слабо ложится на бортовой POV). **Заблокированы:** SCRFD/RetinaFace (InsightFace) — веса non-commercial research-only при MIT-коде; YOLO5Face — GPL-3.0 copyleft; MTCNN — unclear-веса + плохой экспорт каскада. Domain gap к бортовому POV «через стекло» 5–50 м сохраняется у всех permissive-кандидатов (web-обучение); все цифры точности — по заявлению авторов, не измерено нами (эвалуатор FaceDetect не реализован).
**Детально:** `docs/model_research/03_facedetect_facenet.md`

### 4. OCR — распознавание текста номерного знака: nomeroff_ocr
**OCR номера (nomeroff_ocr, CRNN, GPL-3.0 — блокер).** Лучшая открытая замена по совокупности лицензия+кириллица+edge — семейство **PaddleOCR PP-OCRv5 rec** (Apache-2.0 подтверждён И код, И веса): **cyrillic_PP-OCRv5_mobile_rec** как primary и универсальный **PP-OCRv5_mobile_rec + RU-файнтюн** как стратегический secondary. Это единственный кандидат с чистой лицензией кода И весов для кириллицы.
**Domain gap (валидный вывод):** идеального аналога «плате-специфичный + ГОСТ-RU-charset + чистая лицензия кода И весов + готовый ONNX/TRT» НЕ найдено. Все чистые по весам (PaddleOCR/EasyOCR/PARSeq) — общий/scene-text, требуют файнтюна и сужения словаря до ГОСТ-22. Единственный плате-специфичный с RU-данными — **fast-plate-ocr** — несёт **CC BY-NC-ND 4.0** на обучающих данных (готовые веса коммерчески запрещены; чист только MIT-код для переобучения).
**Блокеры:** NVIDIA LPRNet (RU FAIL char 0.59/plate 0.06, EULA), Nomeroff-eu/kz/by (GPL-3.0), TrOCR (license=None, тяжёлый, латиница), OpenALPR (AGPL-3.0). Все цифры — по заявлению авторов, не измерено нами; latency на Orin Nano не мерили.
**Детально:** `docs/model_research/04_ocr_nomeroff.md`

### 5. Color — классификация цвета кузова: bae_model_f3
**Color (bae_model_f3, EfficientNet-B3, 15 классов).** Готовых открытых коммерчески-чистых классификаторов ровно под 15 классов CARS **НЕТ**: все готовые модели дают 7–9 цветов, более широкие наборы либо проприетарны, либо упираются в NC-данные. Ни одна не обучена на бортовом POV (day/night/IR) — фиксируется domain gap.
- **PRIMARY:** дообучить свой **EfficientNet-B3 (timm, Apache-2.0)** под 15 классов на коммерчески-чистых данных (Roboflow CC BY после проверки + своя разметка), ONNX→TensorRT. Оговорка: ImageNet-претрейн → legal review.
- **SECONDARY:** **OpenVINO barrier-0039/0042** (единственный чисто Apache-2.0 на код И веса, но 7 цветов, формат IR); **PaddleClas PULC** (9 цветов, штатный ONNX→TRT, но блокер — веса обучены на VeRi-776 NC).
- **NOT_RECOMMENDED:** Spectrico и chenxyzj (проприетарные веса / ловушка «MIT-код ≠ веса»). Перед поставкой обязателен legal review всех данных обучения и претрейна.
**Детально:** `docs/model_research/05_color_bae.md`

### 6. Make — классификация марки (бренда) ТС: VehicleMakeNet
**Make — классификация марки ТС (VehicleMakeNet, SGIE1).** Baseline проваливается на RU (Top-1 0.083). Открытого коммерчески-чистого make-классификатора **с RU/СНГ-марками не найдено** — все кандидаты US/мировые без RU-словаря.
- **primary:** `timm` fine-grained transfer (КОД Apache-2.0; ВЕСА UNCLEAR — ImageNet/CC-BY-NC, per-model legal review) — единственный путь под RU + бортовой POV через дообучение; `Jordo23/vehicle-classifier` (MIT, US/EU make+model, но штатный .onnx 927KB битый → переэкспорт из .pth).
- **secondary/teacher:** `dima806` и `therealcyberlord` (оба Apache-2.0, ViT-base ~86M, тяжёлые для Orin Nano, метки make+model → агрегация).
- **отклонены:** Spectrico (проприетарный, открыты только обёртки), Pells31 (нет LICENSE), Plate Recognizer (платный закрытый SDK), OpenVINO OMZ (даёт только color/type, не марку).
- Вывод: для RU-продакшна — дообучение собственного классификатора, не готовый open-аналог.
**Детально:** `docs/model_research/06_make_vehiclemakenet.md`

### 7. Type — классификация типа кузова ТС: VehicleTypeNet
**Type — классификация типа кузова ТС (VehicleTypeNet):** готового открытого дроп-ин аналога с 6-классовой таксономией CARS (coupe/largevehicle/sedan/suv/truck/van), бортовым POV (day/night/IR) и нативным ONNX/TensorRT — **НЕТ**.
- **Единственный коммерчески-чистый готовый кандидат** — **OpenVINO barrier-0042** (Apache-2.0 на код И веса, проверено по model.yml), но 4 класса вместо 6, вход 72×72, только IR (нет ONNX) → secondary с маппингом 4→6.
- **PaddleClas PULC / PP-LCNet** — код Apache-2.0 чист, но готовые веса на VeRi (явный non-commercial) → коммерчески запрещены; ценность только как код-база для дообучения с нуля.
- Инкумбент NVIDIA (Model EULA, unclear), AventIQ/MIO-TCD (CC BY-NC-SA), dchen327 (нет LICENSE) — заблокированы; Jordo23/EfficientNet-B4 (MIT) годен лишь как backbone (решает make/model, не тип).
- **Вердикт:** чистого дроп-ина нет; рекомендуемый путь — дообучение лёгкого Apache-2.0/MIT-бэкбона (ResNet-18/PP-LCNet/EfficientNet-B0) под 6 классов на собственном бортовом датасете (снимает И domain gap, И лицензионный риск).
**Детально:** `docs/model_research/07_type_vehicletypenet.md`

### 8. Face embedding — векторное представление лица (планируемая модель): Face embedding (None / Trainable)
**Face embedding (планируемая, None/Trainable)** — открытой модели, одновременно (а) с пермиссивной лицензией НА ВЕСА, (б) edge-оптимальной (~<2M params) и (в) валидированной на automotive/IR-домене, **не существует**. Единственный prod-кандидат — **SFace (OpenCV Zoo, Apache-2.0 на веса)**: готовый ONNX + int8, прямой ONNX→TensorRT, ~1M params → **primary** baseline (точность на бортовом POV/IR нами не измерена, нужен fine-tune). **dlib** (public domain) — лицензионно-чист, но без ONNX-пути → marginal-референс. InsightFace / EdgeFace / ElasticFace = **NC-веса (not_recommended)**; FaceNet / AdaFace / ArcFace-R100-дамп / GhostFaceNets = **unclear-веса (marginal, legal review)** из-за провенанса MS1M/VGGFace2/CASIA. Domain gap к бортовому POV/IR зафиксирован для всех. Целевой путь — дообучить пермиссивный КОД (SFace/EdgeFace-MIT/AdaFace-MIT/GhostFaceNets-MIT) на собственных данных.
**Детально:** `docs/model_research/08_faceembed.md`

## Кросс-выводы

**Семейства/инфраструктуры, охватывающие несколько задач:**
- **Ultralytics YOLO** (v5/v8/v11/v12) — технически сквозное семейство для Detection, LP Detection и Face Detection (через YOLO5Face/YOLO11-pose), но **`AGPL-3.0`** делает его copyleft-блокером для проприетарного CARS на всех трёх задачах. Притом текущий инкумбент `nomeroff_lpd` сам построен на YOLO11x-pose → лицензионный долг уже в стеке. Использование только под платную Enterprise-лицензию либо как R&D.
- **InsightFace** — покрывает Face Detection (SCRFD, RetinaFace) и Face embedding (ArcFace/buffalo-паки): КОД MIT, но **ВЕСА non-commercial research-only** → not_recommended в обеих задачах. README-«MIT» здесь — классическая ловушка «код ≠ веса».
- **PaddleOCR / PaddleClas (PaddlePaddle)** — единственная сквозная коммерчески-чистая (`Apache-2.0` на код И веса) экосистема: PP-OCRv5 закрывает OCR (primary) и частично LP Detection (DBNet det как warp-fallback), PULC даёт код-базу для Color/Type. Цена — лишний шаг paddle2onnx и (у PULC) грязные VeRi-веса, которые годятся только как код для дообучения.
- **OpenVINO Open Model Zoo (vehicle-attributes barrier-0039/0042)** — чистый `Apache-2.0` на код И веса, покрывает Color, Type (и формально Make, но марку не даёт). Ограничения общие: малое число классов, вход 72×72, IR-формат, рантайм Intel (трение на Jetson, нужен community-ONNX→TRT).
- **NVIDIA NGC/TAO (DetectNet_v2-семейство)** — лучший domain-fit и edge-путь для Detection (DashCamNet), Face Detection (FaceDetectIR — единственный штатный IR/ночь), LP Detection (LPDNet), Type (VehicleTypeNet): все под `NVIDIA Model EULA` (unclear → блокер до legal review). DashCamNet и FaceDetectIR остаются ценными как domain-релевантная инициализация для собственного fine-tune.
- **timm (Apache-2.0 код)** — сквозной донор backbone для всех трёх классификаторов (Color/Make/Type): рекомендуемый primary-путь через дообучение собственной головы. Оговорка единая: ImageNet-претрейн-веса → per-model legal review.

## Пробелы и риски

- **Color:** открытого коммерчески-чистого классификатора ровно под 15 классов CARS НЕТ (все готовые — 7–9 цветов, шире — проприетарны/NC). Чистый путь — дообучение timm EfficientNet-B3 на собственных данных.
- **Make (RU/СНГ):** ни одного открытого make-классификатора с RU/СНГ-словарём; baseline VehicleMakeNet проваливается на RU (Top-1 0.083). Только дообучение собственного классификатора.
- **Type (6 классов CARS):** дроп-ина с таксономией coupe/largevehicle/sedan/suv/truck/van + бортовым POV + ONNX/TRT нет; единственный чистый кандидат (OpenVINO barrier-0042) даёт 4 класса/72×72/IR.
- **LP Detection (4 угла + RU/UA + чистая лицензия):** валидный отрицательный результат — такого аналога не существует; keypoints дают только GPL/AGPL/unclear-модели на домене CCPD.
- **OCR (плате-специфичный + ГОСТ-RU + чистые код И веса + ONNX/TRT):** не найдено; чистые по весам — общий scene-text, требуют файнтюна и сужения словаря до ГОСТ-22.
- **Face embedding:** edge-оптимальной (~<2M params) модели с пермиссивными ВЕСАМИ, валидированной на automotive/IR, не существует; SFace — единственный чистый baseline, но домен не закрыт.
- **Domain gap top-view/web → бортовой POV:** все permissive-детекторы/классификаторы обучены на COCO/Objects365/WIDER FACE/web-каталогах (вид сверху или фронтальные студийные фото) — риск переоценки качества; ни один не покрывает «через лобовое стекло 5–50 м» и режимы night/IR (кроме NVIDIA FaceDetectIR под EULA).
- **Биометрия/privacy (Face embedding):** все крупные веса несут privacy-шлейф обучающих данных лиц; коммерческий деплой распознавания лиц требует отдельной правовой оценки.
- **Необходимость дообучения как сквозной вывод:** по 5 из 8 задач (Color, Make, Type, LP Detection с углами, Face embedding) рекомендуемый путь — дообучение чистого backbone на собственном бортовом RU/UA-датасете; источники данных — см.
